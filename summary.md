# SentetikGnostik — codebase summary

Two Twitter/X bots that post short pieces of invented history, generated by Claude and published on a schedule through GitHub Actions.

| Bot | Account | Language | Entry point | Dice | Prompt | History |
|---|---|---|---|---|---|---|
| Errata | @ErrataEternal | English | `bot_claude.js` | `dice.js` | `prompts/claude_en.txt` | `tweet_history.json` |
| Kayıp Defter | @KayipDefter | Turkish | `bot_claude_turk.js` | `dice_turk.js` | `prompts/claude_turk.txt` | `tweet_history_turk.json` |

The premise of each account is never explained in a tweet. Errata publishes corrections from "struck-out drafts" of history (errata slips, treaties, footnotes, obituaries). Kayıp Defter publishes entries from "missing Ottoman defters" (kadı records, vakfiyes, estate inventories, fermans).

## How it works

All the logic is in `engine.js`. Each bot file only calls `createBot({...})` with its own prompt, dice, history file, language and Twitter keys.

One run:

1. **Roll a brief in code** (`rollDice`). It picks a form, device, setting, two motifs, register and length from the dice file, using weighted random picks. Values used recently are excluded (`AVOID`: setting 50 tweets back, motif 40, form 6, device 4, register and length 1). There is a 12% chance of a "callback" to an earlier coined name from history.
2. **Ask Claude** (`buildBrief`, `askClaude`). The system prompt comes from `prompts/*.txt`. The user message is the brief plus the last 8 tweets and recently used numbers (for contrast). Claude writes 3 candidates and picks one, replying as JSON: `{"candidates":[{"text","coined"}...],"pick":0}`.
3. **Filter** (`rejectReason`). It rejects a candidate that is too long (over 270 weighted chars) or too short (under 40), too similar to the last 100 tweets (bigram Jaccard over 0.22), reuses an opener from the last 8, or reuses a number from the last 15. The model's pick is tried first, then the other candidates.
4. **Post and save**. Up to 3 attempts, and every attempt is a paid call. If nothing passes, the run exits with code 2 and skips the slot. Otherwise it posts via `twitter-api-v2` and appends to the history file (kept to the last 500 entries). Each entry stores text, timestamp, tweetId, the dice used and any coined name.

Every call logs token usage and an approximate cost, using the `PRICES` table in `engine.js`. An empty reply aborts immediately instead of retrying.

### Modes and environment variables

```bash
node bot_claude.js                # generate + post
DRY_RUN=1 node bot_claude.js      # generate + save to history, don't post
node bot_claude.js --preview 8    # generate 8, print with dice, save nothing
```

| Variable | Purpose |
|---|---|
| `CLAUDE_API_KEY` | Anthropic key (required) |
| `CLAUDE_MODEL` | defaults to `claude-opus-5-5` |
| `MAX_TOKENS` | defaults to 1500 |
| `TEMPERATURE` | optional, not sent unless set |
| `DRY_RUN` | `1` = don't post |
| `TWITTER_*_CLAUDE` | keys for the English account |
| `TWITTER_*_TURK` | keys for the Turkish account |

If any of a bot's Twitter keys are missing, it falls back to dry-run.

## Dice files

`dice.js` and `dice_turk.js` export `FORMS`, `DEVICES`, `SETTINGS`, `MOTIFS`, `REGISTERS` and `LENGTHS`. Forms have an optional weight `w` and a `setting` rule (`required` / `optional` / `none`). `dice_turk.js` has its own Ottoman-flavoured forms, settings, motifs and registers, and reuses `DEVICES` and `LENGTHS` from `dice.js`. To change the variety of the tweets, edit these files.

## Deployment

`.github/workflows/post.yml` ("post-to-x") runs at 04, 08, 10, 14, 18 and 20 UTC, and on manual dispatch. Steps: checkout, Node 20, `npm install`, a random 0–90s sleep, run each bot, then commit any changed `*.json` history, `git pull --rebase` and push. It uses a `concurrency` group so runs don't overlap.

The workflow runs both bots in separate steps (English, then Turkish). Each step uses `if: !cancelled()`, so if one bot skips or fails the other still runs and the history commit still happens. Each bot needs its own secrets (`TWITTER_*_CLAUDE` and `TWITTER_*_TURK`) plus `CLAUDE_API_KEY`. Both bots post at every scheduled slot.

Don't use GitHub's "Re-run" button on old runs. It replays the old commit and workflow and the history push gets rejected. Use "Run workflow" instead.

## Files

- `engine.js` — shared generator, dedupe filter, Claude and Twitter calls
- `bot_claude.js`, `bot_claude_turk.js` — per-account config and entry points
- `dice.js`, `dice_turk.js` — the random brief ingredients
- `prompts/claude_en.txt`, `prompts/claude_turk.txt` — system prompts (voice and rules)
- `tweet_history*.json` — posted-tweet archive used for dedupe and callbacks (committed by the workflow)
- `bot_gpt.js`, `prompts/gpt_en.txt` — legacy OpenAI bot, standalone, not used by the workflow (`npm run start:gpt` still points to it)
- `.env` — local secrets (gitignored). It still lists `OPENAI_*`, `*_GPT`, `SLOT_SALT` and a few other leftovers that no current code reads.
- `package.json` — ESM project; dependencies are `@anthropic-ai/sdk`, `twitter-api-v2`, `dotenv` and `openai` (only the legacy bot needs `openai`)
